# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

License: GPL-3.0-or-later (`LICENSE`, `NOTICE.md` with a section-7 permission for plugins and platform libraries); `DeckHost.Contracts` and `plugins/DeckHost.Plugin.Obs` are MIT (their own `LICENSE`). Keep GPL code out of Contracts. Community files: `CONTRIBUTING.md` (AI-assisted contributions), `.github/workflows/claude.yml` (`@claude` or the `claude` label on an issue/PR runs Claude Code; write-access users only; docs/maintainers/claude.md), `SECURITY.md`, `CODE_OF_CONDUCT.md`, `.github/ISSUE_TEMPLATE`, `.github/FUNDING.yml`. `docs/reference/actions.md` and `api.md` are generated by `ReferenceDocsTests` (run with `UPDATE_DOCS=1` after changing actions or the Contracts' XML docs; the test fails when they're stale).


DeckHost is a .NET 10 / Avalonia 12 desktop host for physical control surfaces: the MiraBox / StreamDock **N4 Pro**, Elgato Stream Decks (preview) and a browser-based Web Deck. A C++ bridge (`native/MiraBoxBridge`) wraps the vendor StreamDock C++ SDK (git submodule at `native/StreamDock-SDK`) and exposes a flat C ABI that the C# device plugin P/Invokes.

The product direction is `docs/vision/master-plan.md` (the master plan, with Appendix A for what DeckHost does beyond it) and `docs/vision/status.md` (done / partly / not yet per requirement): update the status when a requirement changes, and add new capabilities to Appendix A. Features the plan lists as missing are only built after the maintainer approves the plan for them.

## Commands

Run these from the repository root. Windows is the primary development platform.

```powershell
dotnet build .\DeckHost.slnx -c Debug                                   # C# + native bridge (via CMake)
dotnet build .\DeckHost.slnx -c Debug -p:EnableMiraBoxNativeBuild=false # C# only
dotnet run --project .\DeckHost.App
dotnet test .\DeckHost.Tests -p:EnableMiraBoxNativeBuild=false
dotnet test .\DeckHost.Tests --filter "FullyQualifiedName~MiraBoxModelTests"   # one class
dotnet test .\DeckHost.UiTests                                         # views in Avalonia's headless platform
dotnet build .\plugins\DeckHost.Plugin.Obs                              # -> artifacts\plugins\deckhost.plugin.obs.zip
dotnet run --project .\DeckHost.App -- --check-native                   # load the bridge, list devices, exit
```

- Versions: GitVersion (`GitVersion.MsBuild` in `Directory.Build.props`, rules in `GitVersion.yml`, git-flow: `develop`/`feature/*` next minor `alpha`, `release/x.y.z` `rc`, `hotfix/*` next patch `beta`, `bugfix/*` inherits). CI runs `scripts/version.sh <branch>` once (tag builds: the tag is the version; otherwise it checks the branch out by name and runs GitVersion with `GITHUB_ACTIONS` unset, so it matches a local build) and builds with `-p:DisableGitVersionTask=true -p:Version=`; `AppInfo.Version` is what the app shows: pre-releases get `+<7-char commit>` (from the informational version the SDK stamps), package file names `-<commit>` (`release.yml` outputs `display` and `file`). Releases: push a tag; `.github/workflows/release.yml` builds win-x64, linux-x64 (on Ubuntu 22.04, static OpenCV) and osx-arm64, runs `--check-native` on each publish, packages with `packaging/` and `scripts/package.sh`, and creates the GitHub release (packages unsigned until a certificate is configured: `compose --unsigned windows,macos`, computed from the signing secrets, adds first-start steps; build provenance via `actions/attest-build-provenance`; with the `VT_API_KEY` secret `scripts/virustotal.py` then scans the Windows downloads, warns per flagging engine and `gh release edit`s the notes with `--virustotal`, never failing the release; `build.yml` runs its `selftest`; docs: `docs/download.md#first-start-and-signing`, `troubleshooting.md#if-your-antivirus-blocks-deckhost`, `maintainers/releasing.md#false-positives`). Release notes: `CHANGELOG.md` (Keep a Changelog; add a user-facing line under `[Unreleased]` with each change people notice); `scripts/release-notes.py` checks it (`build.yml`) and composes the notes (the tag's section, else the base version's, else `[Unreleased]` for a pre-release; a stable tag without one fails before building), downloads, checks and the folded PR list (`.github/release.yml` groups by label); `UpdateChecker.UserNotes` cuts at `<!-- deckhost:end-of-notes -->`. The docs site includes it (`docs/changelog.md`, pymdownx.snippets). `build.yml` builds and tests all three on every PR.
- `dotnet publish` copies the native bridge into `plugins/device/deckhost-device-mirabox` too (`PublishMiraBoxBridgeRuntime` in the App project).

- `DeckHost.UiTests` (Avalonia.Headless.NUnit, Skia drawing, no display): `UiTestApp` is DeckHost's colors plus the Fluent theme without the app's start-up; `ViewTests` loads every public parameterless view in `DeckHost.App.Views` and draws a frame; `RenderingTests` check pixels of the custom-drawn views (`WorkflowCanvas`, `DeviceBodyView`) from `CaptureRenderedFrame`. `WorkflowEditorViewModel.Clock` is internal so a test can hold a wait half way. CI runs it after `DeckHost.Tests` (`build.yml`, `release.yml`).
- The plugin catalog tests install the real OBS package, so `DeckHost.Tests` builds the OBS project first (`ReferenceOutputAssembly=false`).
- Tests use NUnit 4 with the constraint model (`Assert.That(actual, Is.EqualTo(expected))`); `TestSetup.cs` makes one class instance per test (constructor = setup, `Dispose` = teardown) and runs classes in parallel; `Expect` has `Single`/`IsType`/`All` helpers that return what they checked. Write tests the way `CONTRIBUTING.md` → Writing tests says (Microsoft's unit testing best practices: `Method_Scenario_Expected` names, `// Arrange`/`// Act`/`// Assert`, one behavior per test, no magic values).
- The tests run on Linux too: `DeckHost.Tests` adds `SkiaSharp.NativeAssets.Linux` there. Wait for the host with `WhenIdleAsync`, not with thread ids or delays: the worker and the test both run on pool threads.

- `DeckHost.Device.MiraBox.csproj` drives the native build. Its targets run in this order: `DetectCMake` → `ApplyStreamDockSdkPatch` (idempotent `git apply` of `native/patches/streamdock-sdk.patch`) → `ConfigureMiraBoxBridge` → `BuildMiraBoxBridge`. CMake is found through `CMakeExePath`, then Visual Studio's bundled CMake, then `PATH`. If none is found, the build only warns and the app runs without device support.
- `native/MiraBoxBridge/CMakeLists.txt` declares hidapi from the SDK's bundled `third_party/hidapi-master.zip` before adding the SDK (the first declaration wins); otherwise the SDK, which looks for it relative to the top-level project, would download hidapi's moving master branch. It also builds everything position-independent so the SDK's static libraries link into the shared library on Linux/macOS.
- On Linux and macOS the bridge's RPATH is `$ORIGIN` / `@loader_path`, and the post-build step copies the SDK's transport library (and on macOS the SDK's OpenCV dylibs) next to it, so the plugin folder is self-contained. `MiraBoxCMakeArgs` (MSBuild property) passes extra CMake arguments, e.g. `-DOpenCV_DIR=` for the static OpenCV from `scripts/build-opencv-static.sh`.
- Native output goes to `native/MiraBoxBridge/out/<Config>/bin/<Config>/`. `DeckHost.App.csproj` copies it to `bin/.../plugins/device/deckhost-device-mirabox/`. `MiraBoxNative`'s `DllImportResolver` loads `MiraBoxBridge` **only** from that folder, after preloading the other native binaries there (hidapi → transport → opencv).
- The submodule is pinned to an upstream commit with `ignore = dirty`. Never commit inside it. SDK changes go into the patch file, per the rule below about third-party code.
- `CMakePresets.json` and the root `CMakeLists.txt` are only for Visual Studio's "Open Folder" mode. Nothing copies from their `out/build/<preset>` output.

## Architecture

The dependency rule: `Contracts` ← `Core` ← `App` → `Device.*` (MiraBox, Elgato, Web) → `Contracts`. **Core must never reference a device plugin.** All hardware access goes through `IDevicePlugin` and `IDeviceOutput`, which are defined in Contracts.

- **`DeckHost.Contracts`**: the plugin-facing surface.
  - Interfaces: `IDevicePlugin` (devices, `DevicesChanged`, `Output`, `InitializeAsync`), `IDeviceOutput` (`TryPushImage`, `TrySetLight`, `Clear`), optional `IDeviceBackdropOutput` (`TrySetBackdrop`), `IDevicePluginContext` (input, connection status, log), `IApplicationPlugin`, `IDeckAction`, `IRenderContext`, `IVariableStore`.
  - Records: `PhysicalControl` carries the device pixel size (`RenderWidth`/`RenderHeight`), `HardwareId` and `LedIndex`, and optional `PhysicalBounds` (mm), `DisplayId`, `Shape`. `DeviceDefinition` (the device descriptor, ADR 0011) has an `IsConnected` flag and optional `DescriptorVersion`, `Identity` (`DeviceIdentity`), `Displays` (`DeviceDisplay`), `Capabilities` (`DeviceCapabilities`, `Has()`), `Limits` (`DeviceLimits`), `PhysicalSize`; `FindDescriptorProblems()` checks consistency (tests run it on every built-in device).
- **`DeckHost.Core`**: the runtime.
  - `DeviceHostService`: every public method only enqueues work onto a `Channel` that **one worker task** processes in order. That worker owns all mutable state, which is why the class has almost no locks. Events are raised on background threads.
  - `ActionRouter`: dispatches input events to actions.
  - `Rendering/`: `SurfaceRenderer` (pinned buffer, one per control size, reused), `SkiaRenderContext`, `SkiaDrawingResources` (cached paints, fonts and decoded images) and `ControlRenderer`.
  - `State/VariableStore`: the Rx variable store.
  - `Profiles/ProfileStore`: profiles as JSON in `%AppData%/DeckHost/profiles.json`.
- **`DeckHost.Device.MiraBox`**:
  - `MiraBoxModels` / `MiraBoxModel`: one entry per StreamDock model the SDK knows (N4 Pro, N4, 293, 293s, M18, XL, M3, N3, N1, K1 Pro, Mini; `For(originType)`), from the SDK's device classes (`_readValueMap` = logical ids, `dispatchEvent` = event types): `MiraBoxControl`s with designer bounds, `ImageKeyId`, `Screen` (main/second), LED, linked display and `MiraBoxInput`s (event + SDK id → input + value); `Describe` builds the `DeviceDefinition` (sizes the SDK reports win), `GetImageKeyId`, `GetLedIndex`, `TryMapInput`, `TracksLongPress`, `KnobsReportNoRelease` (N4, N4 Pro, N3), `HasDeviceConfig` (N4 Pro). Ids: `key.N` (displays, reading order), `touch.N`, `encoder.N` (knobs and the XL/Mini side switches: DIP left/right = rotate, press = press), `button.N` (no display), `screen.N` (second-screen tiles). Only the N4 Pro is `Verified`; the others say so in `Limits.Notes`. Pure and covered by `MiraBoxModelTests`.
  - `MiraBoxDevicePlugin`: device tracking keyed by the SDK's device key (HID path), each session with its `MiraBoxModel` (unknown origin types are logged and skipped), device ids `mirabox.<slug>` then `-2`… (`PrimaryDeviceId` `mirabox.n4pro` always listed), devices seen before remembered in `devices/mirabox-known.json` and listed offline, LED state, long-press synthesis and the `[UnmanagedCallersOnly]` native callback. The udev rule in `packaging/linux` lists every model's USB ids. `IDeviceSettingActions` **Forget this device** (unplugged only) removes a session; forgetting the always-listed N4 Pro is kept as a `Forgotten` entry in the known file. The Elgato plugin has the same action for its remembered decks.
  - `MiraBoxNative`: the P/Invoke layer, using function pointers and UTF-8 strings.
  - `Plugins/PluginCatalog`: system plugins plus installed plugin packages. Packages (`.zip` with `plugin.json`, see `PluginManifest`) install to `%AppData%/DeckHost/plugins/functional/<id>`. They load into a collectible `PluginLoadContext` **from memory**, so the files are never locked and uninstall can delete them immediately. `DeckHost.Contracts` is always shared from the host. Enabled/disabled state and each plugin's origin live in `plugins/state.json`. It is thread-safe (one re-entrant lock) and reports steps through `IProgress<string>`; the UI calls it from `Task.Run` and raises `Changed` on that thread, so view models post to the UI thread.
  - `MiraBoxDeviceSettings` (via `IConfigurableDevicePlugin`; `For(model)` offers what a model has): vibration, boot video, LED/key-light config (`MiraBox_SetDeviceConfig`, N4 Pro only), brightness, and the idle screen (`MiraBox_SendBackgroundFile`; whatever `setBackgroundImgStream` writes persists as the device's standby screen). Stored in `%AppData%/DeckHost/devices/<id>.json` and reapplied on connect. "default" values are never sent.
- **`DeckHost.Device.Elgato`**: Elgato Stream Decks over USB HID (HidSharp; no Elgato software). `StreamDeckModel` (product ids, grid, key image size, flip; the + adds `touch.0–3` linked from `encoder.0–3` and `touch.swipe`), `StreamDeckProtocol` (pure: JPEG key reports `0x02 0x07` and touch-strip reports `0x02 0x0C` in 1024-byte chunks, brightness/reset feature reports, input parsing for keys, dials and touch), `ElgatoDevicePlugin` (hot-plug via `DeviceList.Local.Changed`, one read thread per deck, long-press synthesis; device id `elgato.<pid>.<serial>`; decks seen before are kept in `devices/elgato-known.json` and listed offline; brightness setting). The first-edition Stream Deck and the Mini are `Generation` 1: 24-bit bottom-up BMP key images (`EncodeBmp`: first edition turned 180°, Mini transposed), `Gen1KeyImageReports` `0x02 0x01 page 0 last key+1` padded to `ImageReportLength` (8191 / 1024; the first edition counts pages from 1 and numbers keys right to left in each row, `HardwareKey`), 17-byte feature reports, input `0x01` + one byte per hardware key. The udev rule in `packaging/linux` covers vendor `0fd9`.
- **`DeckHost.Device.Hid`**: generic USB HID devices the user describes in the device creator. `HidDeviceDescription` (JSON in `devices/hid/<id>.json`: vendor/product id, optional top-level `UsagePage`/`Usage`, `HidControl`s with kind key/knob, layout position and `HidInput`: bit/value/relative/absolute at a byte offset of the report as read, byte 0 = report id, optional `ReportId`, `Invert`; knobs may have a `Press`), `HidInputParser` (stateful: Press/Release on change, Rotate steps; absolute positions wrap), `HidLearner` (from idle and active reports: per-bit noise, a byte with more than one noisy bit is a reading; one changed bit → Bit, else Value; knobs → Relative when the byte returns to 0 with small values, else Absolute; direction from a clockwise turn), `HidDevicePlugin` (each description is a device `hid.<id>`, listed offline; opens matching hardware on `DeviceList.Local.Changed`, long-press synthesis; input only, no outputs; `Save`/`Delete`/`Reload`), `IHidDeviceSource` / `HidSharpDeviceSource` (list interfaces with their top usage, listen to one). App: `DeviceCreatorViewModel` + `Views/DeviceCreatorView` (☰ → Add a USB device; listens while shown, learns keys/knobs/pushes, live highlight, drag layout on a Canvas, ids renumbered by position on drop and save, Linux udev rule).
- **`DeckHost.Device.Web`**: the Web Deck, a virtual grid shown in a browser (phone, tablet or a window here). `WebDeckPlugin` runs a TcpListener (HTTP for `deck.html`, an embedded resource, and a WebSocket at `/ws`) on loopback or all interfaces depending on the `sharing` setting (off by default). The page (`/`, `/info`) is open and asks for the pairing code (`XXXX-XXXX` from an unambiguous alphabet, compared normalized and in constant time) and the optional `pin`; `/check` and `/ws` need them (`CheckAccess`; `MaxFailures` wrong tries per address within `FailureWindow` → "wait"). The page remembers them in localStorage and takes `?code=` from a link (then removes it from the address). A changed code or PIN aborts every client. **New pairing code** is an `IDeviceSettingActions` button (Contracts: plugin buttons on the Device settings page, `DeviceSettingActionViewModel` with an optional confirmation). Images go out as PNG (base64 JSON), presses come back as `{type: down|up, key}` (`WebDeckLayout.TryParseInput`); each page has its own bounded send queue. Changing columns/rows raises `DevicesChanged` with new controls.
- **Several devices:** the header shows a device picker (`MainViewModel.DeviceChoices`/`PickedDevice`) when more than one device is listed. `Profiles` holds only the edited device's profiles; the others wait in `_otherDeviceProfiles` (`EveryLayout` is what the host gets and what is saved). `SwitchDevice` swaps them, rebuilds the canvas (`UseDevice`), creates a Default profile for a device without one and asks the host to `Redraw` it. At start the editor opens on the device of the last selected profile; when nothing was picked by hand and the shown device is offline, it follows the first plugged-in hardware deck.
- **`DeckHost.App`**: Avalonia MVVM UI with view models in `ViewModels/`. Themes: dark (default), light or the system's (`AppSettingsData.Theme`, `AppTheme`, `App.ApplyTheme`; DeckHost settings → Look). Colors are `{DynamicResource C.<hex>}` from `Themes/Colors.axaml` (keys named after their dark value, a light value next to it); use those in views, not literal colors.
  - `App.axaml.cs` is the composition root: a Microsoft.Extensions.DependencyInjection container exposed through CommunityToolkit's `Ioc.Default`, with NLog behind `ILogger` (`Platform/Logging.CreateConfiguration`). Pages resolve their view models from `Ioc.Default`. It calls `StartAsync` on `MainWindow.Opened` and, on `Exit`, saves profiles and runs `DisposeAsync`, which blanks the device and shuts the SDK down.
  - `SystemPlugins/`: the plugins that ship with DeckHost: Built-ins (required), Media Controls and System Controls. They derive from `DeckActionBase`. These plugins can be disabled but not uninstalled.
  - `Platform/` is the per-OS code. Actions never call an OS directly: simulated input goes through `SystemControl` (Windows `WindowsInput`/SendInput; Linux playerctl, wpctl/pactl/amixer, xdotool/wtype, loginctl via `ExternalTool`, which passes arguments as a list, never through a shell; macOS system-defined key events via `MacNative` and osascript) and runs on its one ordered background queue (`DeckActionBase.RunQueued`). `SystemVolume` reads the level (cached and refreshed in the background outside Windows, because there it starts a process), `ForegroundAppWatcher` the focused app (Windows API, NSWorkspace, xprop), `SystemMetrics` CPU/memory, `AppSettings` the sign-in entry (Run key, XDG autostart, LaunchAgent). Keep new OS code there, with the pure parts (parsing, key tables) `internal` and covered by `PlatformTests`.
  - On Linux the app needs `SkiaSharp.NativeAssets.Linux` at the SkiaSharp version Core uses: Avalonia brings an older native Skia, and startup fails with "incompatible libSkiaSharp".
  - Single instance: a named mutex everywhere; a second launch signals the first through a named event (Windows) or a named pipe (Linux/macOS).
  - Bindings are immutable `ControlBinding` models. Every edit (drop, the inline editor) builds a new model and calls `MainViewModel.ApplyBinding`. `ControlBindingViewModel` only links a model to the loaded actions.
- **`DeckHost.Core/StreamDeck`**: the Elgato Stream Deck SDK compatibility layer, used for Elgato and OpenAction plugins.
  - `StreamDeckRuntime` starts each `.sdPlugin` as a process (native or `node`) with `-port -pluginUUID -registerEvent -info` and speaks the SD WebSocket protocol through `StreamDeckServer`, a loopback TcpListener that also serves property-inspector pages at `/pi/<context>` and `/plugins/<uuid>/...`.
  - A context is `{deviceId}|{profileId}|{controlId}|{actionUuid}`. Property inspectors are shown in the inline editor through Avalonia's `NativeWebView` (`Avalonia.Controls.WebView`: WebView2, WKWebView, WebKitGTK; data in `%LocalAppData%/DeckHost/webview`, new windows open in the browser, a fallback message when no adapter starts within 8 s); `IDeckAction.GetSettingsPageUri` supplies the URL. Images may be PNG/JPG/GIF or SVG (`Rendering/SvgRasterizer`, Svg.Skia). HTML-based plugins (`StreamDeckManifest.IsHtml`) run through `IHtmlPluginHost`, implemented by `Platform/WebView2PluginHost` (a WebView2 page per plugin in an off-screen, shown tool window, calling `connectElgatoStreamDeckSocket` after load; one shared environment in `%LocalAppData%/DeckHost/webview-plugins` started with `BrowserArguments`, which turn Chromium's background throttling off: without it a hidden page's timers slow down and clock-like plugins freeze). Instance settings live in `%AppData%/DeckHost/streamdeck/settings/instances.json`.
  - MiraBox StreamDock plugins: `Knob` counts as a dial controller (`StreamDeckActionManifest.SupportsEncoder`, `EncoderController` is sent back); a plugin that ends without ever registering is started once more with positional arguments (port, uuid, register event, language: MiraBox's older Node.js template), `RunningPlugin.PositionalArguments`/`TriedPositional`/`Registered`.
  - Restarts: an unexpected process exit (`OnProcessExited`) drops the pending messages, sets `Reappear` and restarts after `RestartDelays` (1/3/10 s; the count resets after `StableRunTime`), then gives up with `ProblemOf`; on the next `registerPlugin` every visible instance gets willAppear again and a redraw. `StatusOf`/`StatusChanged` feed `PluginEntry.ProcessStatus` (Plugins page). HTML plugins aren't restarted (their page lives in WebView2).
  - `StreamDeckApplicationPlugin` adapts a plugin to `IApplicationPlugin`. `IDeckAction.OnAppear/OnDisappear` (called by the host's `UpdateAppearances`) map to willAppear/willDisappear.
  - `PluginCatalog` installs `.streamDeckPlugin` packages into `plugins/streamdeck` (nested archives too). `PluginStore` reads the official DeckHost catalog (`OfficialCatalogUrl`: the `vman26/deckhost-plugins` repo's Pages `catalog.json`, built from `plugins/<id>.json` by that repo's workflows; template and checker in `packaging/plugins-repo` (`tools/catalog.py` check/download/build/from-release/discover; workflows check, publish, submit from an issue form or by hand, weekly discover by GitHub topics, each opening a pull request for review); a 404 is an empty source; `IncludeOfficialCatalog` off in tests), then the user's DeckHost sources (URLs, local catalog files or folders scanned for packages and built plugin folders; listed in `%AppData%/DeckHost/store.json`), OpenAction and the Elgato community archive. Catalogs carry no categories: `PluginCategories.Resolve` derives one. DeckHost catalog entries may carry `sha256` (`StoreEntry.Sha256`, the download is refused on mismatch), `permissions`, and for paid plugins `purchase_url`/`price` (store shows **Buy**, `DownloadAsync` refuses). `PluginStore.FromGitHubAsync` (Store tab → Install from GitHub) turns a repository address into an entry for its newest release's plugin file (`PickReleaseAsset`: no drafts, stable first, .streamDeckPlugin > .dhplugin > .zip, GitHub's `digest` as `Sha256`; also used for catalog entries without a download). `PluginCatalog.RecordUnknownOrigins` backfills the origin of plugins installed before origins were recorded. `StoreMedia` downloads store icons and README images (disk cache `%LocalAppData%/DeckHost/cache/store`) and the README of a plugin's GitHub repository (`GitHubLocation`: repository or page URL, `/tree/<ref>/<folder>` too; raw.githubusercontent.com, so no API rate limit). Elgato archive icons come from `plugins.amankhanna.me/icons/<id>.png` (the catalog's appstore.elgato.com links are dead); installed plugins report `PluginEntry.IconPath` (Stream Deck manifest `Icon`, plugin.json `icon`). The store's **More ▾** shows the README through `Views/MarkdownView` (Markdig AST → Avalonia controls; HTML reduced to its images, breaks and text; SVG badges via `SvgRasterizer.ToPngAtOwnSize`).
- **Linked displays (knob on the touch strip):** `PhysicalControl.DisplayControlId` links a control without a display to one that has one (N4 Pro: `encoder.N` → `touch.N`). `DeviceHostService.FindLinkedBinding` draws the knob's binding there through `ControlRenderer.Draw(..., LinkedBinding)`: the whole zone when the zone has no binding, else a strip (`ControlRenderer.LinkedStripHeight`) on the edge nearest the knob, drawn with `SkiaRenderContext.DrawRegion(compact: true)`. A zone counts as free when `ControlRenderer.HasOwnContent` is false: no binding, or an `IDeckAction.ShowsAppearanceOnly` action (Display Content) with only a background color, which gives the action its own `ControlId`/settings and `IRenderContext.IsCompact`. Actions draw one line when `IsCompact` (`DeckActionBase.DrawCompact`, `RenderContextExtensions.DrawReading`). `ControlAppearance.ShowOnLinkedDisplay` (an init property, so the record's constructor stays binary-compatible) turns it off. A tap on a zone that only shows the knob is dispatched as the knob's Press + Release (`FindTapTarget`). Stream Deck dial actions' `setFeedback` is kept as `DialFeedback`.
- **Screen backdrop:** devices that implement `IDeviceBackdropOutput` get the profile's background color (`ProfileBackdrop.GetColor`) behind the control images; the host sends it before the images and re-sends the images after it. On the N4 Pro this is the SDK's temporary frame background (`MiraBox_SetTemporaryBackground` → `setFrameBackgroundStream`), which covers the stored idle screen (`setBackgroundImgStream`) until `Clear` (`MiraBox_ClearTemporaryBackground`). Without it the idle image showed between the keys of every profile.
- **Preview / test mode:** the host renders every device even when unplugged and raises `ControlFrameRendered` (the canvas images) and `InputReceived` (press feedback). `SimulateInput` runs a fake input through the normal path. Profile backgrounds (`DeviceProfile.Background`) are drawn per control as a slice of one image over the layout (`SkiaRenderContext.DrawLayoutSlice`). GIFs animate through `SkiaDrawingResources` frames at `AnimationInterval` (100 ms).
- **N4 Pro start-up:** the bridge must start the SDK heartbeat, `wakeupScreen()`, and `refresh()` after images. Without the heartbeat the device ignores the host: key presses only toggle its own standby screen.
- **Log:** NLog writes the runtime log, including every input, to `%AppData%/DeckHost/logs/deckhost-<date>.log`; Stream Deck plugin output goes to `logs/plugins/<uuid>.log`, started with a line per run; the run before is kept as `<uuid>.previous.log` (`StreamDeckRuntime.KeepPreviousLog`).
- **Look:** controls are transparent by default: `DeckActionBase` draws an action that has an `Icon` (`Contracts.Icons`, SVG path data on a 24×24 grid, even-odd) through `RenderContextExtensions.DrawTile` in the action's color (`TileColors.From`; white for the neutral palette) on the profile background. With `ControlAppearance.ShowTile` (Customize → Background → the action's tile; `VariableKeys.AppearanceTile`) a key gets a rounded diagonal gradient (`TileColors`, `Palette`) with the icon in white and an optional `Caption`; on a touch zone (wider than 1.3:1) no tile, so the strip stays one surface; compact strips get icon + text. The binding's own background color (`VariableKeys.AppearanceBackground`) replaces the tile and its own image the icon. `DrawReading(..., icon)` lays readouts out like a Stream Deck + dial on a touch zone. `IRenderContext.DrawIcon`, `FillGradientRect` and `DrawRightAlignedText` are default interface members (plugins keep loading); `SkiaRenderContext` implements them and `SkiaDrawingResources.GetIconPath` caches the parsed paths.
- **Icons:** `Core/Icons/IconLibrary` keeps packs in `%AppData%/DeckHost/icons/<id>` in the Stream Deck icon pack layout (`manifest.json` with `Name`/`Version`/`Author`/`URL`/`Icon`/`License`, `icons.json` = `[{path, name, tags}]` relative to `icons/`, `license.txt`); `Install` takes a `.streamDeckIconPack` (a zip with a `<id>.sdIconPack/` folder), a zip or folder of images (a manifest is written). `IconifyClient` searches `api.iconify.design` (`/search`, `/{prefix}.json?icons=`) and builds SVGs; `SaveDownloaded` keeps picked ones in the `iconify` pack with their set's license. `Views/IconPickerWindow` + `IconPickerViewModel` (registered services from `Ioc.Default`). A chosen icon is `ControlAppearance.IconPath` (init property), published as `VariableKeys.AppearanceIcon`; `DeckActionBase.ResolveIcon` prefers it over the action's `Icon`, and `IRenderContext.DrawIcon` draws a file when given an absolute path (single-color SVGs, i.e. with `currentColor`, are tinted; `SkiaDrawingResources.IsSingleColor`).
- **Colors:** `Views/ColorField` (hex box + swatch) opens `Views/ColorPickerPanel` (ColorSpectrum with `SaturationValue`, hue and alpha `ColorSlider`s, HEX/RGB, presets; HSV is the state so the hue survives black/white). `AllowOpacity` adds an opacity slider and Transparent, values `#AARRGGBB` (control backgrounds). Tests use an in-process launcher (`PluginProcessTests`).
- Plugin packages: `plugin.json` `permissions` (`PluginPermissions`: declarations shown to the user, not enforced), `PluginDiagnostics.Check` (also `DeckHost --check-plugin <zip|folder>`, and `PluginEntry.Warnings`; a Stream Deck package's `<uuid>.sdPlugin/manifest.json`, actions and CodePath are checked without starting it, `StreamDeckPackageInfo`), updates keep the previous version in `plugins/.previous/` (`PluginCatalog.RollBack`, Plugins page **Back to v…**).
- Profiles: `ProfileDocument.CurrentVersion` + `ProfileMigrations.Steps` (JSON-tree steps `n → n+1`, backup `backups/profiles-before-v<n>.json`); a newer file is copied to `backups/profiles-from-v<n>.json` before it's saved over.

Runtime flow:

- **Input:** SDK read thread → `OnNativeEvent` → the session's `MiraBoxModel.TryMapInput` → `IDevicePluginContext.ReportInputEvent` → queue → worker → `ActionRouter.Dispatch` → `IDeckAction.Execute` → LED feedback. The device is then marked dirty.
- **Output:** after each batch of work, the worker renders every dirty device. For each control with an image, it draws the background, then the appearance image, then the bound action's own `Render`. The result goes out through `IDeviceOutput.TryPushImage` **only if the pixels differ from the last frame pushed**. The bridge encodes with OpenCV, using the SDK's image helper (which applies the N4 Pro's 180° rotation), and calls `setKeyImgFileStream`. N4 Pro key IDs 6–15 are the main keys and 1–4 are the touch-strip zones.
- **Pixel format:** the host renders RGBA; OpenCV (the SDK's `RawCanvas`) is BGRA. `EncodeRgba` in the bridge swaps R and B while copying. Copying the bytes unchanged shows red as blue on the device.
- **Knob release:** the N4 Pro reports a knob press but no release; `MiraBoxDevicePlugin` reports a Release `KnobReleaseDelay` after each press (Stream Deck plugins get dialDown and dialUp).
- **UI:** `MainViewModel` marshals host events with `Dispatcher.UIThread.Post`. Never touch view-model collections from a host or SDK callback.

Conventions that span files:

- Control IDs: `key.0`–`key.9` (reading order), `touch.0`–`touch.3`, `touch.swipe`, `encoder.0`–`encoder.3` on the N4 Pro; other devices use the same prefixes, plus `button.N` and `screen.N` on MiraBox models. The N4 Pro's SDK IDs are numbered from the bottom-left, so `key.0` is SDK key 11 (see `MiraBoxModels.BottomLeftRows`).
- Build variable-store keys with `DeckHost.Contracts.VariableKeys`, which produces `devices.{deviceId}.{controlId}.{suffix}`. Never write them as string literals. Actions and renderers communicate only through these keys.
- An action is identified by `"{pluginId}:{actionId}"`. Duplicates are logged, not thrown.
- Saved bindings whose plugin isn't loaded are kept and written back unchanged (`ProfileItemViewModel.AddUnresolvedBinding`).
- Native ABI: every export in `MiraBoxBridge.cpp` must be declared in `MiraBoxBridge.h` and have a `[LibraryImport(EntryPoint = "...")]` with the identical name in `MiraBoxNative.cs`. Exports address devices by device key, return `>= 0` on success or a negative `MiraBoxResult`, and never let a C++ exception escape. The managed callback must not block or throw: the SDK holds a lock while calling it.

## Project guidelines (from `.github/copilot-instructions.md`)

- Don't modify third-party code (the StreamDock SDK) when a project-side workaround is possible. Unavoidable SDK changes go into `native/patches/streamdock-sdk.patch`.
- Two plugin categories: device plugins (hardware) and application/functional plugins (features such as media control).
- Render per control (`setKeyImgFileStream`), not one 800×480 framebuffer through `setBackgroundImgStream`. The designer should show what the device would show.
- Use the SDK's feature controllers: RGB through `setLedBrightness` / `setLedColor` / `setSingleLedColor`, input through `ReadController`, device configuration through `Configer`.
- UI behavior:
  - Dragging an assignment off a control, or dropping it anywhere in the window that isn't a control, removes it. A cancelled drag keeps it.
  - The drag visual shows the control.
  - Dragging a mapped control onto another moves its whole binding (`MainViewModel.MoveBinding`): swap when the target is taken, Ctrl copies. A drag only starts after the pointer moves a few pixels, so click and double-click still work.
  - Selecting a control shows its editor below the device (`MainViewModel.Editor`, a `ControlCustomizationViewModel` rebuilt on selection, profile switch and any outside change to that binding; its own edits apply through `OnEditorChanged` without a rebuild). Revert restores the binding from when it was selected, Remove clears it. Hotkey settings (`ActionSettingKind.Hotkey`) can be recorded from a key press.
  - Profiles: the Profiles page creates, duplicates, renames, reorders and deletes them. `DeviceProfile.AutoSwitchApps` and `ProfileDocument.AutoSwitchEnabled` drive automatic switching. `Platform/ForegroundAppWatcher` (Windows, 500 ms polling, ignores DeckHost itself) feeds `AutoProfileSelector`. When no app matches, it returns to the manually chosen profile (`_manualProfileId`, which is what `selectedProfileId` saves).
  - `Views/ColorField` compares with the text it last showed, not only `_syncing`: `TextChanged` and `ColorChanged` arrive after `Sync` returns, and used to write the shown default (#000000, #FFFFFF) into every control (and profile) whose editor was opened.
  - Undo/redo (`MainViewModel.Undo.cs`): `ApplyBinding` (and `ApplyWorkflow` for another layout) records each binding change with before/after (`RecordBindingChange`); quick edits of one control within `UndoMergeWindow` merge, `Grouped` makes a move/swap or the starter layout one step; history clears on `LoadProfiles` and `SwitchDevice`. Header arrows and Ctrl+Z/Ctrl+Y (`MainWindow.OnWindowKeyDown`, not in text boxes or pages).
  - Right-click a control for Customize (selects it) / Remove. The editor has the action's settings, the Multi Action steps (drop actions from the list at a position, drag ⠿ to reorder: `StepsDropZone` handles the drag and marks it handled so the window's handler skips it; `InsertStep`, `MoveStepTo`, `DropIndex`), text and image, and for knobs the light. Cards go in two columns from 820 px.
  - Multi Action is an action type, and actions are grouped by plugin in collapsible groups. Display Content is hidden from the list: setting a text or image on an empty control creates it.
  - Main window layout (like the Stream Deck app): header (menu, device and profile picker, update pill, tool buttons), the device at a fixed row height (400, a `GridSplitter` below) so it never resizes with the lists, the editor below, the action list on the right (plugin groups collapsed by default with `ListIcon`s: `IDeckAction.ListIcon` default member; DeckHost actions' tile icon or `PaletteIcon`, Stream Deck actions' manifest icon), and an optional debug panel (`AppSettingsData.ShowDebugPanel`). Settings, Plugins, Profiles, Device settings and Update are `UserControl` pages shown in the window (`IPageHost`, `Pages.Open/Close`, Back and Esc). Drags show a ghost with icon and name (`IDragGhostHost`, `DragGhost`), drawn in the window's overlay since platform drag and drop shows none. The Plugins page installs .zip packages, enables/disables plugins, uninstalls installed ones and shows the devices with their firmware version.
- Firmware: the StreamDock SDK can only *read* the firmware version (`transport_get_firmware_version`); it has no update/flash API. Don't add update logic without an official MiraBox protocol. The API for devices that can: optional `Contracts.Interfaces.IDeviceFirmware` (`GetFirmwareInfo`, default members `CheckForFirmwareAsync`/`InstallFirmwareAsync`; records in `Contracts/Models/Firmware.cs`). `Core/Firmware/FirmwareService` does the rest for every plugin: connected only, one at a time, HTTPS downloads checked against the release's SHA-256 (none → refused), `IDeviceHostService.SetDevicePaused` (default member; the host skips images, lights and input of a paused device, `WhenIdleAsync` before the plugin writes, redraw on resume). MiraBox, Elgato (feature report 0x05 / gen-1 0x04, `StreamDeckProtocol.FirmwareVersion`) and HID (USB release number) only report versions. UI: Device settings → Firmware card (`FirmwareViewModel`: check, install a release or a file, confirmation, progress); `DeviceSettingsService` also opens for devices that only have firmware.
